# Deploying to Hostinger (FTP-only, no SSH)

How Leenmore Hub goes onto Hostinger shared hosting under a subdomain, using FileZilla for
transfers. There is no SSH on this plan, so nothing is built on the server: composer, npm and
the asset build all run locally, and the handful of commands that genuinely need a CLI are run
through **hPanel cron jobs** — Hostinger's cron executes arbitrary shell commands, which is the
escape hatch that replaces SSH.

---

## Prerequisites — check these first

**PHP 8.4 is mandatory.** `composer.json` says `^8.3`, but `composer.lock` resolves Symfony 8 and
`openspout` 5.7, which both require **PHP >= 8.4.1**. On PHP 8.3 the app fatals on boot. If the
Hostinger plan cannot offer 8.4, stop here — the dependency set has to be downgraded first
(`composer update` with a `config.platform.php` override), which is a separate piece of work.

Two things that catch people out and are already handled in this repo:

- Nothing uses the `public` filesystem disk. Every file is written to `storage/app/private` and
  streamed back by a controller ([ReceiptFileController.php](../app/Http/Controllers/ReceiptFileController.php),
  [ProjectResourceFileController.php](../app/Http/Controllers/ProjectResourceFileController.php),
  [ReportFileController.php](../app/Http/Controllers/ReportFileController.php)). **No `storage:link`
  is needed** — normally the thing that blocks FTP-only Laravel deploys.
- `RosterPdfRenderer::libreOfficeBinary()` short-circuits when `proc_open` is unavailable. Shared
  hosting disables it, and Symfony's `Process` throws rather than failing soft, so without that
  guard every 명부양식 PDF would hard-fail instead of falling back to mPDF.

## Step 1 — hPanel setup (before touching FileZilla)

1. **PHP version** — Advanced → PHP Configuration → **8.4**.
2. **Extensions** (same page): `mbstring`, `gd` (mPDF), `zip` + `xmlreader` (openspout), `intl`,
   `fileinfo`, `bcmath`, `curl`, `openssl`, `pdo_mysql`, `iconv`, `exif`.
3. **PHP options**: `max_execution_time` ≥ 120, `memory_limit` ≥ 256M, `upload_max_filesize` and
   `post_max_size` ≥ 32M (receipt scans and 주주명부 uploads).
4. **Subdomain** — Domains → Subdomains → create `hub`. If the dialog offers a **custom folder**,
   point it at `domains/<domain>/leenmore-hub/public` (Layout A below). Note the absolute path
   hPanel reports — every cron command needs it.
5. **SSL** — issue the free certificate for the subdomain, then enable **Force HTTPS**.
6. **Database** — Databases → MySQL → create a database and user. Hostinger prefixes both with
   `uXXXXXXX_`. Save the credentials.
7. **FTP** — Files → FTP Accounts. Use the **main** account; sub-accounts are often chrooted to
   `public_html`, and this deploy writes one level above it.

## Step 2 — build the deploy bundle locally

Run from the repo root. Everything lands in a scratch directory so the dev checkout is never left
in a `--no-dev` state.

```bash
BUILD=/tmp/leenmore-deploy          # anywhere outside the repo

npm run build                       # regenerates public/build

rsync -a --delete \
  --exclude '.git' --exclude 'node_modules' --exclude 'vendor' \
  --exclude 'tests' --exclude 'audit' --exclude 'docs' --exclude 'workflows' \
  --exclude '.claude' --exclude '.vscode' --exclude '.lando.yml' \
  --exclude '.env' --exclude '.env.example' --exclude 'phpunit.xml' \
  --exclude 'dependabot.yml' --exclude 'CLAUDE.md' --exclude '.editorconfig' \
  --exclude 'database/database.sqlite' --exclude '.phpunit.result.cache' \
  --exclude 'storage/logs/*' \
  --exclude 'storage/framework/views/*' \
  --exclude 'storage/framework/cache/data/*' \
  --exclude 'storage/framework/sessions/*' \
  --exclude 'storage/framework/testing/*' \
  --exclude 'storage/app/private/livewire-tmp/*' \
  --exclude 'storage/app/private/imports/*' \
  ./ "$BUILD/"

cd "$BUILD"
composer install --no-dev --optimize-autoloader --no-scripts --no-interaction
rm -f bootstrap/cache/*.php         # must not ship a manifest listing dev providers
php artisan --version               # smoke-test the --no-dev autoloader; regenerates a clean manifest
zip -qr ../leenmore-hub.zip . -x '*.DS_Store'
```

Notes on the choices here:

- **`--no-scripts`** skips `package:discover`, which would otherwise need a `.env`. The manifest is
  deleted and regenerated by the smoke test instead. Shipping the dev-built
  `bootstrap/cache/packages.php` alongside a `--no-dev` vendor makes the app boot-fail on
  `Laravel\Pail\PailServiceProvider`.
- **Do not** add `--classmap-authoritative` — Livewire resolves classes outside the classmap.
- **Do not** run `config:cache`, `route:cache` or `icons:cache` locally; they bake in local paths
  and local `.env` values.
- `resources/fonts/nanum-gothic/` and `resources/templates/email-to-worker.xlsx` are runtime
  assets, not build-time ones — they must stay in the bundle.
- `storage/app/private/{submissions,receipts,resources,worker-rosters}` ships so existing
  downloads work. `imports/` is excluded: those are abandoned upload temp files that
  `ShareholderImport` deletes on completion, and no DB row references them.

Expect roughly **72 MB / ~11,900 files** in the zip (`vendor/` is 164 MB unpacked, of which mPDF's
bundled fallback fonts are 94 MB — they are needed for the Korean PDF fallback, don't strip them).

## Step 3 — production `.env`

Keep it **out** of the zip and upload it separately, so a redeploy can never overwrite the live
one. Start from `.env.example` and set:

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_KEY=            # copy verbatim from the local .env — nothing in the DB is encrypted,
                    # but reusing it avoids needing key:generate on a server with no CLI
APP_URL=https://hub.<domain>        # must match the real scheme+host or Livewire breaks
APP_LOCALE=ko
LOG_LEVEL=error

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_DATABASE=uXXXXXXX_…
DB_USERNAME=uXXXXXXX_…
DB_PASSWORD=…

SESSION_DRIVER=database
SESSION_SECURE_COOKIE=true
QUEUE_CONNECTION=database
CACHE_STORE=database
FILESYSTEM_DISK=local

MAIL_MAILER=smtp
MAIL_SCHEME=smtp                    # 587 + STARTTLS; if the handshake fails, smtps + port 465
MAIL_HOST=smtp.hostinger.com
MAIL_PORT=587
MAIL_USERNAME=app@leenmore.com
MAIL_PASSWORD=…
MAIL_FROM_ADDRESS="app@leenmore.com"
MAIL_FROM_NAME="Leenmore"

LIBREOFFICE_BIN=                    # absent on shared hosting → mPDF fallback

ESIGNON_BASE_URL=https://docs.esignon.net/api/
ESIGNON_COMPANY_ID=…
ESIGNON_MEMB_EMAIL=…
ESIGNON_MEMB_PASSWORD=…
```

Nothing here is needed for the MCP server ([mcp.md](mcp.md)) — its Passport signing keys are
generated on the server in Step 7, not configured here.

<details>
<summary>Unless you would rather keep no key files on disk at all</summary>

`PassportServiceProvider::makeCryptKey()` prefers `PASSPORT_PRIVATE_KEY` / `PASSPORT_PUBLIC_KEY`
and only falls back to `storage/oauth-*.key` when they are empty. So you *can* generate the pair
locally with `php artisan passport:keys` and paste the PEM blocks in instead. It reads them through
`str_replace('\n', "\n", …)`, so a single-line `\n`-escaped value works and a multi-line `.env`
value is not required. There is no advantage here over Step 7 — it just puts a private key in
`.env`.

</details>

> ⚠️ `APP_URL` matters twice over once MCP is deployed. The OAuth discovery documents are built
> from it, so if it is wrong — or still `http://` — Claude and ChatGPT will fail the connector
> handshake with an unhelpful error, even though the site itself looks fine.

> ⚠️ Real SMTP is live the moment this file lands. Any click on 활동가에게 이메일 보내기 during a
> client demo sends real mail to real 활동가. Ship `MAIL_MAILER=log` first if that is not wanted —
> a later `.env` edit is enough to switch, provided no config cache exists (Step 7).

## Step 4 — upload with FileZilla

- **Connection**: host `<domain>` or the server hostname from hPanel, port 21, protocol
  *FTP – File Transfer Protocol*, encryption *Require explicit FTP over TLS*, **Passive** mode.
- Transfer → Transfer type → **Binary** before sending the archives.
- Target directory: `/domains/<domain>/` — a sibling of `public_html`, **not** inside it.
- Upload `leenmore-hub.zip` and `leenmore.sql.gz` (Step 6). Then hPanel → Files → **File Manager**
  → right-click the zip → **Extract** into `/domains/<domain>/leenmore-hub/`. Delete the zip after.
  The archive has no wrapper directory — its entries are `app/`, `vendor/`, `public/`, … so it
  extracts straight into whatever folder you choose.
- Upload the production `.env` to `/domains/<domain>/leenmore-hub/.env`. Check FileZilla didn't
  save it as `.env.txt`.
- Permissions (right-click → File permissions → *Recurse into subdirectories*): directories `755`,
  files `644`. Confirm `storage/` and `bootstrap/cache/` are writable.

If File Manager chokes on the 12k-file archive, split it: zip `vendor/` on its own and the rest
separately, then extract each. If FileZilla refuses to navigate above `public_html`, the account is
chrooted — switch to the main FTP account, or use Layout C.

## Step 5 — document root

**Layout A — custom document root (preferred).** The subdomain already points at
`/domains/<domain>/leenmore-hub/public`. Nothing more to do: `.env`, `storage/` and `vendor/` sit
above the web root and `public/.htaccess` ships with the bundle.

**Layout B — fixed document root** (hPanel forces `public_html/hub`). Copy the *contents* of
`leenmore-hub/public/` into `public_html/hub/` — including `.htaccess`, `build/`, `images/`,
`favicon.*`, `robots.txt` — delete any Hostinger-placed `index.html`/`default.php`, then edit the
three paths in `public_html/hub/index.php`:

```php
if (file_exists($maintenance = __DIR__.'/../../leenmore-hub/storage/framework/maintenance.php')) {
require __DIR__.'/../../leenmore-hub/vendor/autoload.php';
$app = require_once __DIR__.'/../../leenmore-hub/bootstrap/app.php';
```

(`public_html/hub/` → `../../` → `domains/<domain>/` → `leenmore-hub/`.)

**Layout C — last resort**, only if FTP is locked inside `public_html`: app at
`public_html/hub/app-root/` with an `.htaccess` there containing `Require all denied`, and
`public/` contents in `public_html/hub/`. Least safe — avoid unless forced.

## Step 6 — import the database

```bash
lando ssh -s database -c "mysqldump -ularavel -plaravel \
  --default-character-set=utf8mb4 --single-transaction --no-tablespaces \
  --set-gtid-purged=OFF --skip-add-locks laravel | gzip -9 > /tmp/leenmore.sql.gz"
docker cp leenmorehub_database_1:/tmp/leenmore.sql.gz ./leenmore.sql.gz
```

**Do not import this through phpMyAdmin.** The dataset is 806 MB across 23 tables — 1.2M
`project_shareholders` and 1.0M `shareholders` rows — which is ~550 MB of SQL, 124 MB gzipped.
phpMyAdmin will hit its upload cap or time out partway, leaving a half-populated database.

Import it with the `mysql` client through a **one-off cron job** instead (see Step 7 for how to run
one). Upload `leenmore.sql.gz` to the home directory via FileZilla first:

```
zcat ~/leenmore.sql.gz | mysql -u uXXXXXXX_user -p'PASSWORD' uXXXXXXX_db 2> ~/import.log
```

Set the job to every minute, wait for one run (several minutes for 2.2M rows), then delete the job
and check `~/import.log` is empty. Delete the dump and the log afterwards — they contain the full
dataset and the DB password respectively.

Then, in phpMyAdmin, clear the volatile tables carried over from local and confirm the import:

```sql
TRUNCATE TABLE sessions; TRUNCATE TABLE cache; TRUNCATE TABLE cache_locks;
TRUNCATE TABLE jobs; TRUNCATE TABLE job_batches; TRUNCATE TABLE failed_jobs;

SELECT COUNT(*) FROM migrations;                      -- expect 32
SELECT migration FROM migrations ORDER BY id DESC LIMIT 1;
                       -- expect 2026_07_24_064052_create_oauth_device_codes_table
SELECT COUNT(*) FROM project_shareholders;            -- expect ~1,202,454
```

A correct `migrations` table is what tells any future `migrate` run there is nothing pending.

The last five of those 32 are Passport's `oauth_*` tables, which the MCP server needs. They ride
along in the dump **only if `php artisan migrate` was run locally before dumping** — if the count
comes back 27 and the newest row is `2026_07_05_000002_create_worker_email_recipients_table`, the
dump predates them. That is harmless: run `migrate --force` as a one-off cron (Step 7) after the
import and it adds the five empty tables without touching anything else.

Finally, review `users` before the client logs in: deactivate or re-password test accounts, and
make sure the client's admin account exists with a known password.

## Step 7 — cron jobs

hPanel → Advanced → Cron Jobs. First run a throwaway job `php -v > ~/phpver.txt` — Hostinger's
**CLI** PHP version can differ from the web one. If it is not 8.4, use the versioned binary
(e.g. `/opt/alt/php84/usr/bin/php`) everywhere below.

| Frequency | Command |
|---|---|
| Every minute (or the smallest hPanel allows) | `/usr/bin/php /home/uXXXXXXX/domains/<domain>/leenmore-hub/artisan schedule:run >/dev/null 2>&1` |
| Every 5 minutes | `/usr/bin/php /home/uXXXXXXX/domains/<domain>/leenmore-hub/artisan queue:work --stop-when-empty --tries=3 --max-time=280 >/dev/null 2>&1` |

Both are required, not optional:

- The **queue worker** is what actually sends worker emails. `SendWorkerEmail` is a queued job on
  the `database` driver — with no worker, jobs pile up in the `jobs` table and nothing sends, with
  no visible error. `--stop-when-empty` and `--max-time` keep each run short-lived, which is what
  shared hosting tolerates.
- The **scheduler** drives the hourly `esignon:sync` declared in [routes/console.php](../routes/console.php).

**Running any artisan command without SSH:** create a temporary cron job with the command, set it
to every minute, wait for one execution, then delete the job. This is how you run `migrate --force`,
`esignon:sync --project=…`, `optimize:clear`, or the database import above.

### One-off: Passport signing keys (required for MCP)

Run once, through the same temporary-cron pattern, then delete the job:

```
/usr/bin/php /home/uXXXXXXX/domains/<domain>/leenmore-hub/artisan passport:keys
```

Passport signs every OAuth access token with an RSA keypair, so without this the consent screen
appears but the connector never finishes authenticating. The command writes
`storage/oauth-private.key` and `oauth-public.key` **and chmods them to 600 and 660 itself**, which
is the whole reason to generate them here rather than upload them.

Both files are gitignored (`/storage/*.key`), so a redeploy will not overwrite them, and
`passport:keys` refuses to clobber an existing pair without `--force`. Generate once and leave them
alone — regenerating invalidates every connected assistant's token.

> ⚠️ If you upload the keys by FTP instead, you **must** set `oauth-private.key` to `600` and
> `oauth-public.key` to `660` in FileZilla (right-click → File permissions). FTP defaults to 644, and
> at 644 `league/oauth2-server` raises an `E_USER_NOTICE` that Laravel — which runs under
> `error_reporting(-1)` — converts into a thrown `ErrorException`. The result is not a warning in the
> log: every MCP request returns a 500.

Optional, once the site is verified and stable:

```
/usr/bin/php /home/uXXXXXXX/domains/<domain>/leenmore-hub/artisan optimize
/usr/bin/php /home/uXXXXXXX/domains/<domain>/leenmore-hub/artisan icons:cache
```

> ⚠️ After `optimize`, `.env` edits have no effect until `optimize:clear` runs. On a preview site
> that is still being tweaked, it is reasonable to skip this entirely.

## Step 8 — verify

1. `https://hub.<domain>/up` returns the health response — autoloader, `.env` and DB all resolve.
2. The login page renders styled, with the Instrument Sans webfont. An unstyled page means
   `public/build/` is missing or the document root is wrong.
3. Log in as an admin: dashboard, 프로젝트 list and a project detail page show the imported data,
   and Livewire interactions (search, pagination, modals) work. Livewire errors here almost always
   mean `APP_URL` doesn't match the real scheme/host.
4. Open a receipt attachment and a project resource file — confirms `storage/app/private/**`
   uploaded intact and is readable.
5. In the worker area, complete a 활동 submission including an image upload — proves `storage/` is
   writable and the upload limits are sane.
6. **Email**: queue one worker email to your own address. The `jobs` table should gain a row, then
   lose it within ~5 minutes when the queue cron fires. If it lands in `failed_jobs`, check
   `storage/logs/laravel.log`. The attached 명부양식 PDF must open with legible Korean text — that
   is the mPDF + Nanum Gothic fallback path working.
7. **Scheduler**: confirm `esignon:sync` ran within the hour (rows gaining 전자위임연락처 /
   전자위임날짜). Force it early with a one-off cron running `artisan esignon:sync --project=<id>`.
8. `https://hub.<domain>/.env`, `/storage/logs/laravel.log` and `/composer.json` must all return
   403/404.
9. Hit a nonsense URL — a plain 404, never a stack trace. If you see a trace, `APP_DEBUG` is still
   on or a stale config cache is in place.
10. **MCP**: `https://hub.<domain>/.well-known/oauth-authorization-server` returns JSON naming an
    `authorization_endpoint` and `token_endpoint` on the same host. If the host is wrong, `APP_URL`
    is wrong. Then connect a client following [mcp.md](mcp.md) and ask it for a project's 판단 tally.

    These are two separate proofs. Discovery metadata is assembled from `APP_URL` without signing
    anything, so passing it says nothing about the keys — those are first exercised when a client
    exchanges its authorisation code for a token. A 500 at *that* point, having reached the consent
    screen, means the keys are missing or their permissions are wrong (Step 7), not that anything is
    misconfigured.

## Redeploying later

Repeat Steps 2 → 4 with these narrowings:

- **Code or asset change only**: re-zip without `vendor/` and `storage/app/`, extract over the top,
  then delete `bootstrap/cache/*.php` and `storage/framework/views/*` so Blade and the package
  manifest recompile. If `optimize` was run, also `optimize:clear` via one-off cron.
- **`composer.lock` changed**: ship `vendor/` too.
- **New migrations**: run `artisan migrate --force` through a one-off cron. Never re-import the
  database — that destroys whatever the client has entered.
- **Never** overwrite the server `.env` or `storage/app/private/**` from a local bundle once the
  client is using the site.
